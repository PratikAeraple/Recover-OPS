DISPOSABLE LAB / EVIDENCE

Only the fixture
is disposable.

The recovery demo generates its own data, creates a separate copy, simulates loss and corruption, then verifies a clean restore. A child web service binds only to loopback.

Observed scenario

  1. Generate a fresh temporary fixture and SHA-256 manifest.
  2. Copy into a separate disposable recovery directory and remove the source fixture.
  3. Restore into a new destination and verify size and digest.
  4. Alter a separate copy and confirm that integrity validation fails.
  5. Start a loopback-only health service; terminate it and detect the outage.
  6. Start a fresh child process and confirm the health identity recovers.

Expected state sequence: UP → DOWN_DETECTED → UP_RECOVERED.

Run and inspect

python3 src/recoverops.py demo
python3 -m unittest discover -s tests -v

The temporary workspace is removed on exit. The output reports counts and status without fixture contents. A local drill duration is not a production RTO.
